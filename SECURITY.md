# Security

Do not post signing certificates, private keys, provisioning profiles, account information, cookies or full device logs in a public issue.

For a vulnerability that could expose accounts or private data, use **Security → Report a vulnerability** in this GitHub repository when private vulnerability reporting is available. If that option is unavailable, open an issue requesting a private contact without including the vulnerability details or sensitive material.

Security fixes target the latest published release and the current default branch. Website adapter failures without a security impact can be reported using the [support instructions](.github/SUPPORT.md).

Only sign packages obtained from a release you trust, verify their checksums, and keep your signing files outside the checkout. Public releases contain unsigned IPAs; they must not contain a developer's certificate or embedded provisioning profile.
